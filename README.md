# Ambler

Ambler turns a shared event, trip or activity into a private, cinematic story built from everyone’s photos, clips, notes, route data and real event signals.

The product is organised around **Capture → Build → Relive**:

- **Capture** — create an event, invite people by QR/link, collect private guest media and notes, and optionally record the route.
- **Build** — deterministic story curation scores media, builds the timeline and route, selects a story family/theme, creates factual insights and assembles the storybook. Generative AI is not required.
- **Relive** — open through the cinematic story reveal, swipe through the finished story, or share it privately on the web with an expiring token.

## Current implementation

- Expo Router + React Native + TypeScript
- Supabase Auth, Postgres, Storage, RLS, Realtime and Edge Functions
- email/social auth plumbing plus anonymous guest sessions
- event creation with persistent description, event type and story theme
- 52 event types with 14 narrative families and a large deterministic content library
- QR invite links
- no-install browser guest contribution flow
- native media upload, compression/thumbnails and upload progress
- browser photo/video upload for invited guests
- private gallery with persisted heart reactions
- event notes/captions that feed the generated story
- optional GPS route capture and Route Replay
- browser-safe Route Replay for shared stories
- story engine with media scoring, curation, timeline, insights, copy, music selection and themes
- server-side story generation
- cinematic **Your Story Is Ready** reveal
- private expiring web-story links with refreshed signed media URLs
- Short / Standard / Epic story pacing with burst- and location-aware chapter planning
- richer hiking, sport, cycling, running and group-workout metrics when the captured data supports them
- organiser story editing: copy, captions, page order, cover media, theme, music and section regeneration
- organiser moderation, archive and storage-clean permanent deletion
- PDF / print-layout export foundation
- deterministic source and story-engine tests plus Android CI definitions

## Important setup

Copy `.env.example` to `.env` and configure Supabase plus the public Ambler web origin.

For no-account QR guests, enable **Anonymous Sign-Ins** in Supabase Authentication.

Apply migrations in order and deploy the public story Edge Function:

```bash
supabase functions deploy public-story --no-verify-jwt
```

## Run

```bash
npm install
npx expo install --check
npx expo start
```

Android preview build:

```bash
eas build --platform android --profile preview
```

## Project structure

- `app/` — Expo Router screens and public join/share routes
- `src/components/` — reusable UI, event, media, route and storybook components
- `src/features/` — auth, events, contributions, media, location, sharing, music and story engine
- `src/stores/` — Zustand application stores
- `src/styles/` — design tokens and story themes
- `supabase/migrations/` — database schema and RLS
- `supabase/functions/` — server-side story generation and token-gated public story delivery
- `docs/` — product, roadmap, architecture, quality, privacy and release documentation

For the detailed architecture map, see [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## Build status

The current checkpoint passes the deterministic source-integrity and story-engine regression suites. Expo/native direct dependencies are pinned to the Expo SDK 52 compatibility matrix; the stale lockfile that previously resolved newer incompatible majors has been removed and should be regenerated by the first clean networked install. The isolated build environment used for this checkpoint cannot complete a clean dependency/Gradle download, so semantic TypeScript and Android build verification are delegated to the included GitHub Actions / a networked build machine. Production release is also intentionally blocked until all soundtrack licences are confirmed in `assets/music/music-manifest.json`.

Do not equate source presence with product acceptance. The remaining verification and completion sequence is maintained in [`docs/ROADMAP.md`](docs/ROADMAP.md).
